# `/learn` スキル設計 — 作業内容の知識定着

- 作成日: 2026-09-28
- 参考: 大賀愛一郎「『LLMへ渡したくない仕事』を考える」(Zenn, 2026-09-19) https://zenn.dev/algoartis/articles/73f4da4aa13dcc

## 目的

Claude Code に任せた作業（技術・設計判断・コード）を、自分が説明できる状態にする。

記事の原則に従い、摩擦を二種類に分ける。

| 摩擦 | 担当 |
|---|---|
| 身につけたい能力から遠い摩擦（材料集め・整理・順序立て・図・問題作成） | Claude |
| 身につけたい能力そのもの（予測・想起・自分の言葉での言い直し・確認事項の整理） | 自分 |

## スコープ

- 対象: Claude Code の作業内容と、プロジェクトの作業ディレクトリ
- 対象外: 日次振り返り（日記 vault 連携）、hook による自動提案・自動生成
- トリガー: 手動のみ（`/learn [テーマ]`）

## 構成

| 要素 | 内容 |
|---|---|
| スキル | `~/.claude/skills/learn/SKILL.md`。WSL 側・Windows 側の両方に配置 |
| vault | 新設 `Documents\Obsidian Vault\学習\`（WSL: `~/vault/学習/`）。登録は手動（Obsidian で「フォルダを vault として開く」）。`obsidian.json` は編集しない |
| ノート | `YYYY-MM-DD <テーマ>.md`。frontmatter: `source`（元プロジェクトの絶対パス）、`created`、`tags` |
| hook | 追加しない |

## フロー

1. **テーマ決定**: 引数があればそれを使う。無ければ直近の作業から候補を3件提示し、AskUserQuestion で選ばせる
2. **材料収集**: 会話内容と作業ディレクトリのコードを読む（読み取りのみ）
3. **執筆**
   - 前提知識を「先に知る必要がある順」に並べる
   - 根拠は `file:line` で示す
   - 用語は初出で定義し、未習の専門用語を増やさない
   - 「初心者向けに分かりやすく」の方向へ書かない（分かった気を助長するため）
4. **図**: Mermaid で書く
5. **描画確認**（Obsidian CLI）
   1. `obsidian vault=学習 open path=<ノート>`
   2. `obsidian dev:dom selector=".mermaid svg" total` で図の描画数を取得し、Mermaid ブロック数と照合する。エラー要素の有無も確認する（セレクタは実機で確定）
   3. `obsidian dev:screenshot path=<png>` → 画像を Read して目視確認する
   4. 崩れがあれば修正して 1 に戻る。最大3回。直らなければ報告して止める
6. **完了報告**: ノートのパスを示す。Gemini Notebook へのアップロードは手動（自動化しない）

## ノートの構成

```markdown
---
source: <元プロジェクトの絶対パス>
created: YYYY-MM-DD
tags: [learn]
---
# <テーマ>

## 前提知識（順番に）
<!-- Claude が書く -->

## 本題
<!-- Claude が書く。図・出典 file:line 付き -->

## 答えを見る前に予測
<!-- Claude は問いのみ書く。予測は自分で書く -->

## 想起問題
<!-- Claude が問題を書く。解答は折り畳み -->
1. 問題文
> [!answer]- 解答
> 解答本文

## 自分の言葉で説明
<!-- 空欄。Claude は書かない -->

## 確認したいこと（3行メモ）
1. ここまでは、こう理解している:
2. 根拠は、資料のこの部分:
3. ここを確かめたい:
```

「予測」「自分の言葉で説明」「3行メモ」の本文を Claude が埋めることは禁止する。これがこの仕組みの核である。

## Gemini Notebook の扱い

- NotebookLM の規約では、通常利用のアップロード資料・クエリは学習にも人間レビューにも使われない（フィードバック送信時を除く）。固有情報を含む教材のまま手動でアップロードしてよい
- 認証情報・個人情報を教材に含めない（執筆時に Claude が除外する）

## 前提作業（ユーザー）

1. Obsidian の Settings → General → 「Command line interface」を ON にし、ターミナルを再起動する
2. `学習` フォルダを vault として登録する

## 検証

- Windows 側 Git Bash で `obsidian help` が応答すること（アプリ本体の起動のみで終わらないこと）
- WSL 側 Claude から Windows 側 CLI を呼べるか確認する。呼べない場合、WSL 側では描画確認を省略し、その旨を完了報告に明記する
- 実テーマ1件で試作し、描画確認のループが一巡することを確認する

## 保留事項（本設計の対象外）

- `rules/trinity-development.md` の Gemini / agy 送信制限の緩和。Antigravity の学習・人間レビューのオプトアウト手段をユーザーが確認するまで保留する。`/learn` は agy を使わないため、本設計を阻害しない
