# 一枚絵（インフォグラフィック）

1920x1080 の1枚の HTML を描き、PNG に書き出す。

固定するのは「決まり」だけで、「見た目」はお題ごとに決める。一枚絵はお題ごとに世界観もキャラも変わるのが正しく、見た目を固定するとどの絵も同じ顔になる。

| 層 | ファイル | 固定するもの | お題ごとに決めるもの |
|---|---|---|---|
| 決まり | `constraints.css` | キャンバスの大きさ・余白・最小の文字サイズ（18px）・フォント | — |
| 値 | `theme-template.css` | 役割の名前（`--ig-color-todo` など） | 名前に入れる実際の値（色・文字の段階・線・角） |
| 部品 | `parts.html` | 役割の名前（`ig-部品__要素`、種類は `data-*`）・並べ方・内側の余白 | 枠の形（四角／巻物／リボン／吹き出し）・線の質感・影 |
| 検証 | `check.js` | はみ出し・隠れ・重なり・文字サイズ・絵文字の検査。`n: 0` が合格 | — |

`parts.html` の灰色の点線と四角は「テーマ未設定」を示す仮の見た目で、真似をしない。キャラクターは部品に含めず、お題ごとに配役表から描く。

## 判断の基準

作る前とレビューの時は、この表で判断する。

| 観点 | 基準 |
|---|---|
| 読む順番 | セクションに番号を振り、上→下か左→右の一方向に流す。番号の付いた枠が4〜5個を超えたら削る |
| 情報量 | 1セクションは2〜3行のフレーズかセリフ。説明文は書かない。詳しい説明は添える記事（Confluence 等）に任せる |
| 主役 | 絵が主役で、文字は絵に添える。文字だけの箱が並んだら、キャラのセリフか小道具に置き換える |
| 世界観 | 1つの比喩（リレー・旅・冒険など）で見出しと絵をそろえる |
| 登場人物 | 人が出てこない題材でも「動く人と物」を数えて配役する（例：頼む人／書き手／受け手／渡される物）。同じキャラを役割を変えて何度も出し、表情とポーズで話を進める |
| Before / After | 「その道具を入れる前と後の、仕事の進め方」を比べる。道具が出す物の有り無しを比べない |
| 実例 | 実際に使った場面を例に使うとき、その場面でたまたま扱っていた作業の中身（監査・特定の案件など）を持ち込まない。例文は誰の仕事にも当てはまるものに置き換え、「例」と明記する |
| 強調 | 一番強調するのは ToDo（やること）だけ。注意点は控えめにする。セクションの番号と手順の番号は形か色で区別する |
| 見た目 | 前の一枚絵（自分や作り手が作ったものを含む）の配色・枠の形・キャラを流用しない。世界観から決め直す |
| 出典 | 見る人に意味が通じる名前で1行。ファイル名や「同じディレクトリの〜」は書かない |
| 載せないもの | 案件固有の情報・顧客情報・機密・認証情報・参加者の実名（実名を出すかはユーザーに確認） |

社内の発表ルールがある場合は、その項目（例：何ができる？／何がうれしい？／どうやって使う？／注意点は？）を見出しにする。

## 環境の制約

- 絵文字フォントが無い（豆腐になる）。キャラ・イラスト・アイコンはすべてインライン SVG で描く
- 日本語フォントは IPAexGothic のみ。外部リソース（CDN・Web フォント・画像 URL）は使えない
- 成果物は CSS と SVG を中に書いた1ファイルの HTML。`constraints.css` と埋めたテーマは成果物の `<style>` へ写す（`<link>` で参照しない）
- 表示される文字は 18px 以上。下端に 24px 以上の余白を残す

作業前に `fc-list | grep -i emoji` と `fc-list :lang=ja family` で、環境が変わっていないか確かめる。

## 手順

作業ディレクトリは `/tmp/infographic-<題材>/` に新しく作る。前の作品があるディレクトリは使わない。

### 1. 中身を固める

載せる文言をセクションごとに書き出し、ユーザーの確認を取る。文言の根拠（記事・SKILL.md・議事録など）を1つ決め、根拠に無い機能や数字を足さない。

### 2. 世界観・配役表・テーマを決める

世界観を1つ決め、そこから配役表とテーマの値を決めて、ユーザーの確認を取る。

```
世界観：（例）リレー
| 役 | 何をするか | 見た目 | 出てくるセクション |
|---|---|---|---|

テーマ：
- 配色の方針（世界観から。例：運動会なら紅白と青空）
- 枠の形（四角／巻物／リボン／吹き出し など、世界観に合うもの）
- 線の質感（手描き風・クレヨン・まっすぐ など）
```

テーマの値は `theme-template.css` の空欄を埋める形で書く。決め方に迷ったら、作り手に世界観と配役表を渡してテーマ案を2つ出させ、選ばせてよい。

### 3. 配置案を選ばせる

作り手（手順4と同じ相手）に、中身と配役表を渡して ASCII の配置案を2〜3個出させる。

- 横46文字×縦18行以内。罫線 `┌─┐│└┘├┤┬┴┼`、キャラは顔文字で位置を示す
- 各案に、読む順番・選ぶ理由・弱点を添えさせる

AskUserQuestion の `preview` に図を入れて選ばせる。HTML はまだ作らない。

### 4. 作り手に組ませる

作り手は、前の作品を見ていない新しい相手にする。前の作品を見た作り手は、キャラや配置を引きずる。

- Codex：新しいセッションで `codex exec -s read-only --skip-git-repo-check -o <出力.html> "<依頼文>" < /dev/null > codex.log 2>&1`。続きは `codex exec ... resume <session id>`（`session id:` はログから取る）
- Claude：この会話を知らない新しいサブエージェント。「指定ディレクトリの外を読まない」と書く

依頼文には、次を全部入れる。

1. 手順1の中身と、手順2の配役表と埋めたテーマ
2. 採用した配置案の図
3. このファイルの「判断の基準」と「環境の制約」
4. `constraints.css` と `parts.html`（作業ディレクトリへコピーして渡す）と、次の指示
   - 部品は `parts.html` の役割の名前と構造で組む。色・寸法はテーマの変数と `constraints.css` の変数だけを使う
   - `parts.html` の灰色の見た目は仮のもので、真似をしない。枠の形・線・影はテーマと世界観に合わせて描く
5. 出力形式：HTML 本文のみ（`<!DOCTYPE html>` から `</html>`）

### 5. 測って直す

```bash
agent-browser set viewport 1920 1080
agent-browser open file://<出力.html>
agent-browser eval --stdin < ~/.claude/skills/infographic/check.js
agent-browser screenshot <出力>.png
```

- `n` が 0 でなければ、出力された項目と数値（要素名・はみ出し量・位置）をそのまま作り手に渡して直させる。「被っている」のような曖昧な言い方で頼まない
- `n` が 0 になったら、画像を1枚 Read して目で見る（色・絵の崩れ・キャラの重なりは測れない）
- 直す前の版は `<出力>.v1.html` のように残す

### 6. 書き出す

```bash
agent-browser set viewport 1920 1080 2
agent-browser open file://<出力.html>
agent-browser screenshot <出力>@2x.png
agent-browser close
```

3840x2160 の PNG を成果物として渡す。`/tmp` は再起動で消えるので、保存先をユーザーに伝える。

## 完了条件

- `check.js` の `n` が 0
- 画像を目で見て、読む順番どおりに読める・キャラと文字が重なっていない
- 手順1で確認した文言がすべて載り、それ以外の文言・数字が増えていない
- 確かめていないこと（2倍画像を開いていない等）を報告に書く
