# 怠惰ラダー

> 実装前の探索順。出典と導入記録は `~/.claude/docs/ponytail/PROVENANCE.md`

コードを書く前に、最初に成立する段で止まる。

1. **作る必要があるか**（YAGNI）→ 不要なら作らず理由を一行
2. **既にこのコードベースにあるか** → 再利用。書く前に探す
3. **標準ライブラリで済むか**
4. **ネイティブ機能で済むか** → `<input type="date">`、CSS、DB制約
5. **導入済みの依存で済むか** → 数行のために新規依存を足さない
6. **一行で書けるか**
7. どれも該当しなければ、動く最小限

ラダーは問題を理解した後に走る。触る範囲を読み、実際の流れを追ってから段を選ぶ。理解を省いた小さな差分は二つ目のバグ。

## 削ってはいけないもの

- 信頼境界での入力検証
- データ損失を防ぐエラーハンドリング
- セキュリティ・アクセシビリティ
- 明示的に要求されたもの（完全版を求められたら作る。蒸し返さない）

非自明なロジックには、壊れたら落ちる検証を1つ残す。既存のテスト基盤があればそれに従う（`verification-loop.md` 優先）。

天井が分かっている簡略化（グローバルロック・O(n²) 走査）には `ponytail:` コメントで天井と昇格パスを書く。`/ponytail-debt` が台帳化する。
