# Resolving Merge Conflicts

## 手順

1. **現状を把握する。** マージ / リベースの進行状態、履歴、衝突しているファイルを確認する。

2. **各衝突の一次情報を辿る。** それぞれの変更が**なぜ**入ったのか、元の意図は何かを理解する。
   コミットメッセージを読み、PR を確認し、元の issue / チケットまで遡る。
   ここを飛ばした解消は、動くように見えて意図を壊す。

3. **hunk ごとに解消する。** 両方の意図を可能な限り保存する。
   両立しない場合は、**このマージの目的**に合う側を採り、捨てた側のトレードオフを記録する。
   **新しい振る舞いを発明しない。** 必ず解消しきる。`--abort` で逃げない。

4. **プロジェクトの自動チェックを走らせる。** 典型的には型チェック → テスト → フォーマット。
   マージによって壊れたものを直す。

5. **マージ / リベースを完了する。** すべてステージしてコミットする。
   リベース中なら、全コミットが載りきるまで継続する。

## 完了条件

`rules/verification-loop.md` に従う。型チェック・テストがクリーンであることを**実際に実行して**確認し、
解消時に捨てた側のトレードオフがあればユーザーに報告する。
