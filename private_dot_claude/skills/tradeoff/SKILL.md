# Tradeoff Analysis

提案された実装計画のメリット・デメリットをパフォーマンス・コスト・セキュリティ・保守性の観点から具体的に分析し、十分な情報に基づいた意思決定を支援する。

**原則**: 分析を提供するが最終判断は下さない。意思決定権は常にユーザーにある。

## 分析軸

### 1. パフォーマンス
- レイテンシへの影響（P99 含む）
- スループット・スケーラビリティ
- ボトルネックとなりうる箇所

### 2. コスト
- インフラコストへの影響
- 運用・保守コスト（障害対応・監視含む）
- 開発コスト（実装・テスト工数）

### 3. セキュリティ
- 新たに生じる攻撃面
- 既存セキュリティ境界への影響
- コンプライアンス・監査要件

### 4. 保守性
- コードの複雑度変化
- 将来の変更容易性
- チームの理解・習熟コスト

## 実行手順

**Step 1: コンテキスト把握**
既存コード・設計ドキュメント・`CLAUDE.md` を読み、現在のアーキテクチャを把握する。

**Step 2: 提案内容の明確化**
実装計画が曖昧な場合は、具体的な変更箇所・採用する技術・置き換える既存の仕組みを確認する。

**Step 3: 4軸分析**
各軸について、具体的なコード箇所・数値・障害シナリオを根拠として分析する。

**Step 4: 代替案の提示**
現提案以外の選択肢を少なくとも1つ挙げ、比較する。

## 出力フォーマット

```markdown
## トレードオフ分析: <実装名>

### メリット
| 軸 | 内容 | 影響度 |
|----|------|--------|
| パフォーマンス | ... | 高/中/低 |
| コスト | ... | 高/中/低 |
| セキュリティ | ... | 高/中/低 |
| 保守性 | ... | 高/中/低 |

### デメリット・リスク
| 軸 | 内容 | 影響度 | 緩和策 |
|----|------|--------|--------|
| パフォーマンス | ... | 高/中/低 | ... |
| コスト | ... | 高/中/低 | ... |
| セキュリティ | ... | 高/中/低 | ... |
| 保守性 | ... | 高/中/低 | ... |

### 代替案との比較
| 案 | 主なメリット | 主なリスク |
|----|------------|-----------|
| 現提案 | ... | ... |
| 代替案A | ... | ... |

### 判断のポイント
<意思決定に必要な観点を箇条書きで>

### 意思決定支援
- **優先軸の確認**: プロジェクトで最も重視する軸は？（パフォーマンス/コスト/セキュリティ/保守性）
- **リスク許容度**: 代替案でのリスク増加を許容できるか？
- **撤回可能性**: 後で変更できるか？（撤回可能なら小リスク選択も可）

> 最終判断はユーザーに委ねる。本分析は判断に必要な情報を提供するのみ。
```

## 注意事項

- **主観を排除**: 「良い/悪い」ではなく「メリット/デメリット」で表現
- **具体的根拠**: 数値・シナリオ・コード箇所を示す。根拠なき評価は禁止
- **代替案必須**: 現提案だけでなく比較対象を必ず提示する
