# audit-skills

カスタムスキルのSKILL.mdを読み込み、品質・効率・安全性を分析し、検出した問題を自動修正する。

## 実行形式

```
/audit-skills [対象] [+観点]
```

### 対象パラメータ

| 指定 | 意味 |
|------|------|
| 省略 / `@all` | 全スキル検索 |
| `@プロジェクト名` | 指定プロジェクト内のスキル |
| スキル名 | 個別スキル指定 |

### 観点パラメータ

| 指定 | 意味 |
|------|------|
| 省略 / `+core` | コア10観点 |
| `+security` | コア + セキュリティ拡張 |
| `+portability` | コア + 移植性拡張 |
| `+reliability` | コア + 信頼性拡張 |
| `+full` | 全観点統合 |

---

## 実装ステップ

### Step 1: 対象スキル収集

以下3つのパス層を並列検索する：

1. `~/.claude/skills/*/SKILL.md`（グローバル）
2. `<カレント>/.claude/skills/*/SKILL.md`（カレント）
3. `<カレント>/*/.claude/skills/*/SKILL.md`（サブプロジェクト）

- audit-skills自身は除外する
- Glob未検出時はBashでフォールバック

### Step 2: メタデータと内容読み込み

- 対象スキルのSKILL.md全てを並列Read
- プロジェクトのCLAUDE.mdを読み込む
- Skill()呼び出し先スキルも読み込む
- frontmatter / 本文行数 / 他スキル呼び出し名を記録

### Step 3: チェック実行

#### コア10観点（C1〜C10）

**C1: 指示矛盾**
同一操作の異なる手順、「する/しない」両立、スキル間仕様不一致

**C2: 指示不備**
エラー対処・判断基準の曖昧さ、分岐欠落、引数バリデーション不足、ロールバック無し

**C3: 指示過剰**
500行超スキル、重複指示、冗長な例示、汎用性喪失（200行超の場合は references/ への分離を検討）

**C4: セキュリティ**
機密ファイル除外、破壊操作確認、dangerouslyDisableSandboxの明確性、mainブランチ警告

**C5: 速度最適化**
並列可能ステップの逐次実行、&&チェーン分割、重複ロジック

**C6: スキル間整合性**（複数対象時のみ）
役割重複、自前再実装、実装統一、前提条件不一致、用語統一

**C7: allowed-tools整合性**
使用指示のツール未登録、登録済み未使用、Agent/Skill指定不整合

**C8: トリガリング精度**
短すぎるdescription、フレーズ不足、類似スキル競合、機能とのギャップ

**C9: 保守性**
CLAUDE.md重複、ハードコード値、責務過大（100行超複数機能）、過小（15行以下低独立性）

**C10: 使用性**
直感性欠落、確認頻度不適切、結果報告不十分、成功/失敗フォーマット未定義

#### セキュリティ拡張（+security）

- 責任追跡性: コミット署名・ログ出力の追跡可能性
- Sandbox詳細分析: dangerouslyDisableSandbox全箇所の対象コマンド・理由・代替案評価
- 外部通信リスク: 取り消し困難操作の確認フロー
- 権限昇格分析: allowed-tools組み合わせの想定外権限取得リスク

#### 移植性拡張（+portability）

- 環境依存明示: OS・シェル・ツールバージョン・systemd前提の記述
- パスハードコード: ユーザー固有・絶対パス直書きの有無
- プロジェクト分離: グローバルスキルへの固有ロジック混在チェック

#### 信頼性拡張（+reliability）

- 障害許容性: 外部ツール失敗・ネットワーク・ファイル不在への対処
- 回復性: 途中失敗・状態変更後失敗のリカバリ手順
- 成熟性: 空入力・大量ファイル・権限不足の対処

### Step 4: レポート出力

```
## スキル監査レポート

対象: N個 | 観点: +core（等）

### 個別スキル結果

#### [スキル名]（行数:NN, スコープ:グローバル/プロジェクト）
| 観点 | 重大度 | 指摘 |
|------|--------|------|
| C#: 内容 | 重大/改善/情報 | 具体指摘 |

### スキル間指摘（複数対象時のみ）
| 観点 | 対象 | 重大度 | 指摘 |
|------|------|--------|------|
| C6 | skill1/skill2 | 重大/改善 | 具体指摘 |

### サマリー
- 重大（自動修正済み）: N件
- 改善（自動修正済み）: N件
- 情報（参考）: N件
```

#### 重大度基準

| 重大度 | 基準 | 修正方針 |
|--------|------|----------|
| **重大** | 実行誤り・セキュリティリスク・データ損失・実行時エラー | 即時自動修正 |
| **改善** | 効率悪化・保守困難・UX低下 | 自動修正 |
| **情報** | 軽微な余地・スタイル統一 | 修正しない（報告のみ） |

---

### Step 5: 自動修正

重大・改善の指摘をEditツールで順次修正する。修正方針：

- **C1（指示矛盾）**: 矛盾箇所を削除し、より明確な記述に統一する
- **C2（指示不備）**: エラー対処・ロールバック手順を補足する
- **C3（指示過剰）**: 重複指示・冗長な例示を削除しコンパクトにまとめる
- **C4（セキュリティ）**: 破壊操作前の確認フロー・機密ファイル除外を追記する
- **C5（速度最適化）**: 逐次ステップを並列実行に書き換える
- **C7（allowed-tools整合性）**: frontmatterのallowed-toolsを実態に合わせて更新する
- **C8（トリガリング精度）**: descriptionにトリガーフレーズを補強する
- **C9（保守性）**: ハードコード値を変数化・責務過大スキルは分割提案を添える
- **C10（使用性）**: 成功/失敗の出力フォーマットを明記する

修正完了後、変更差分のサマリーを出力する。
