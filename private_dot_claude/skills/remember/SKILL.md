# /remember スキル

## 目的

会話中の指摘・フィードバックを構造化し、将来のセッションで同じミスをしないよう記録する。

## 引数

```
/remember                    # 直近の指摘・フィードバックを対象にする
/remember private関数を使うな  # 引数テキストをそのまま記録対象にする
```

## 実行手順

### 1. 置き場の大分類判断

保存先を決める前に、まず4つの置き場のどこに書くべきかを判別する。

- **軸A: 誰に効かせる？** → チーム全員 / 自分だけ
- **軸B: どの範囲？** → このプロジェクトだけ / 全プロジェクト横断

判別フロー:

```
チームも知るべき? ──Yes──▶ ① .claude/（git commit）
      │No
他リポジトリでも効かせる? ──Yes──▶ ② 個人グローバル
      │No                              ├ 最初からの原則 → ~/.claude/CLAUDE.md・rules/
      ▼                                └ 学んだ教訓     → ~/.config/claude/lessons/
③ ネイティブ memory（~/.claude/projects/.../memory/）
```

| 置き場 | 条件 | 例 |
| ------ | ---- | -- |
| ① `.claude/`（commit） | チーム共有・プロジェクト固有 | アーキ制約・命名規則・ナレッジ |
| ② `~/.claude/CLAUDE.md`・`rules/` | 自分・全プロジェクト・最初からの原則 | 三位一体・出力トークン圧縮 |
| ② `~/.config/claude/lessons/` | 自分・全プロジェクト・事後の教訓 | ARN split教訓・レビュー誤認パターン |
| ③ ネイティブ memory | 自分・プロジェクト固有・非commit | TGW ID・進行中チケット・環境固有値 |

判定の一言:
- 「新メンバーも知るべき？」→ Yes なら ①
- 「他リポジトリでも同じこと言う？」→ Yes なら ②
- 「commit するほどでもないが作業再開時に思い出したい」→ ③
- ②の中: 「憲法（最初の原則）」= CLAUDE.md/rules / 「判例（学んだ教訓）」= lessons

このスキルの以降の手順（②`~/.config/claude/lessons/`への保存）は、上記判別で②かつ「学んだ教訓」に該当した場合のフロー。①③に該当する場合はそれぞれの置き場に応じて別途保存する。

### 2. 記録内容の特定

- 引数あり → 引数テキストをルール化する
- 引数なし → 直近の会話から「訂正・否定・フィードバック」を抽出する
- 対象が特定できない場合はユーザーに確認する

### 3. 分類 → 書き込み

保存先ファイルを Read し、同趣旨ルールの重複がないか確認してから書き込む。

| 種別 | 条件 | 保存先 |
|------|------|--------|
| コードスタイル | 実装パターン・構造・命名に関するもの | `~/.config/claude/lessons/code-style.md` |
| レビュー挙動 | /code-review での誤認・誤指摘パターン | `~/.config/claude/lessons/review-behavior.md` |
| PJ固有ルール | 具体的な設定値・リソースID・プロジェクト名等を含み、**他リポジトリでは通用しない**ルール | `.claude/knowledge/{カテゴリ}.md` |
| 既存カテゴリ該当 | `~/.config/claude/lessons/*.md` の既存ファイルのテーマに合致するもの | 該当する既存カテゴリファイル |
| 新規カテゴリ候補 | 上記どれにも該当せず、かつ同一技術領域で今後も知見が増えそうなもの | **新規ファイル作成の可否をユーザーに確認**してから `~/.config/claude/lessons/{新カテゴリ}.md` を作成 |
| 真に雑多 | 他のどのカテゴリにも属さない単発的な内容のみ | `~/.config/claude/lessons/general.md` |

**PJ固有ルールか その他一般か迷ったら「この内容、別のプロジェクトでも同じことを言うか？」を自問する。Yes なら その他一般、No なら PJ固有ルール。**

**`general.md` に入れる前に「これは今後同じ技術領域の知見が増えそうか？」を自問する。Yes なら新規カテゴリファイル作成をユーザーに確認する。`general.md` は最終手段。**

**判断が難しい場合はユーザーに確認してから書き込む。**

重複あり → 既存エントリの`**count:**`を+1し、必要なら内容を更新する
重複なし → ファイル末尾に追記する（`**count:** 1`から開始する）

保存先ファイルが存在しない場合は新規作成する。

### 4. 書き込みフォーマット

```markdown
### {ルール名}（YYYY-MM-DD追記）
**count:** 1
**ルール:** {具体的・行動可能なルール。「〜すること」「〜しないこと」で書く}
**適用:** {いつ・どのような状況で適用するか}
```

### 5. 完了報告

記録した内容・保存先・重複有無をユーザーに提示する。
書き込みエラー（権限不足など）が発生した場合はエラー内容を明示し、代替手段（手動コピー用テキスト）を提示する。

## Claudeが /remember を提案するタイミング

以下のいずれかに該当したら会話の末尾に一言添える：
`→ この指摘を /remember で記録しますか？`

1. **ユーザーが訂正・否定した** — 「違う」「間違い」「やめて」「そうじゃない」等のキーワードが含まれ、Claudeの行動を指摘していると判断できるとき
2. **ユーザーが明示した** — 「覚えて」「記録して」「メモして」と言ったとき（即実行）
3. **Claudeが自覚したとき** — バグ修正・レビュー中に「この知識があれば最初からミスしなかった」と判断したとき
