# Code Naming

名前は読み手が最初に出会う説明である。名前が悪いと、意図を掴むために実装を読む羽目になり、
その処理のコストや副作用が見えなくなる。

## 適用範囲

- 対象は**語彙の選択のみ**。大文字小文字の規則（camelCase / snake_case 等）は言語・プロジェクトの慣習に従う
- プロジェクトのコーディング規約が優先される。ただし**命名についてはこのスキルを優先**する
- 言語仕様で決まっている名前、既存ライブラリの慣習には適用しない
- **新規コードにのみ適用**する。既存の名前は明示的に依頼された場合のみ変更する

## 判断プロセス

1. その処理を**日本語一文で説明する**。「〜を取得する」で終わったなら、理解が足りていない。何をしているのか掘り直す
2. 動詞を英語に置き換える（迷ったら下のルール1の一覧を引く）
3. 対象を名詞で表す
4. 修飾が要るか決める（時制・状態・不確実性）
5. **音読する。** 英文として成立しない名前は、読み手も同じところで詰まる

## ルール

### 1. 新規コードで `get` を使わない

何をしているのかが `get` に埋もれる。実際の動作で置き換える。

| 動詞 | 使う場面 |
|---|---|
| `load` | ストレージから読む |
| `fetch` | ネットワーク越しに取る |
| `find` | 条件で探す（見つからないことがある） |
| `list` | 集合を並べる |
| `build` | 組み立てる |
| `calculate` | 計算する |
| `resolve` | 候補から選ぶ・解決する |
| `convert` | 変換する |
| `extract` | 一部を取り出す |
| `findOrCreate` | 探して無ければ作る |

### 2. 名前の重さを実処理のコストに一致させる

軽い名前で I/O・ネットワーク呼び出し・ループを隠さない。
逆に、読むだけの処理に重い名前を付けない。名前を見ただけで**コストが予測できる**こと。

### 3. 目的駆動で命名する

広すぎる名前はクラスを肥大させる。関心ごとに割る。

- ✗ `Product` → ○ `ReservedItem` / `StockItem` / `ShippingItem`
- 却下語: `Manager` `Controller` `Util` `Helper` `Data` `Info` `Item`

### 4. boolean は条件式に置いて英文になること

`== true` を付けずに `if` に入れて文法的に成立するか確かめる。

- 使う: `is` + 形容詞/過去分詞 / `has` + 名詞/過去分詞 / `can` + 原形 / `should` + 原形 /
  `needs` + 名詞・動詞 / 三人称単数の動詞
- 使わない: `check~` / `is` + 動詞原形 / 動詞のみ

### 5. 曖昧な動詞を具体語に置き換える

`check` `change` `process` `handle` `manage` `do` は何が起きるかを隠す。
`compare` も判定基準を隠すので、`equals` / `contains` / `isOlderThan` のように基準を名前に出す。

### 6. 対義操作は対の語彙で揃える

`add`/`remove`、`insert`/`delete`、`create`/`destroy`、`open`/`close`、
`start`/`stop`、`enable`/`disable`、`show`/`hide`。片方だけ別系統の語を使わない。

### 7. 略語を使わない

例外は `i` のような極短のループ変数と、確立した略語（`id` `url` `http` `db` `json`）のみ。

### 8. 品詞を一貫させる

- クラス・型・変数は名詞、関数・メソッドは動詞始まり
- インターフェースは形容詞または役割を表す名詞
- コレクションは複数形、要素は単数形
- コールバックは時制を含める（`onCompleted` `beforeUpdate`）

## 書き上げたあとのチェック

- [ ] 新規に `get` で始まる名前が残っていない
- [ ] 名前だけで I/O・ネットワークの有無が分かる
- [ ] クラス名が1つの関心に絞れている
- [ ] boolean が条件式で英文になる
- [ ] 曖昧な動詞が残っていない
- [ ] 対義操作が対で揃っている
- [ ] 略語が例外の範囲に収まっている
- [ ] 複数形・単数形が実際の中身と一致している
- [ ] 同義語が混在していない（用語が一貫している）
