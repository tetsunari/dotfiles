# Agent Design Review Skill

AIエージェントの設計品質を5軸で体系的にレビューする。「動作するか」ではなく「効率的・堅牢・コスト最適か」を評価基準とする。

## When to Activate

- 「仕様書を見て」「設計レビューして」「これで問題ないか確認して」
- 「エージェント設計のフィードバックほしい」
- エージェントのハーネス・ツール・プロンプト設計について判断を求められた時
- **Note**: Read/Grep のみで実行可能な inject モード。コードベース確認が必要な場合は code-explore エージェント併用推奨。

## Review Process

**ステップ1: 入力確認**
以下を把握してからレビュー開始。不足時は一度だけ質問する。
- エージェント数と各役割
- 使用ツール一覧
- システムプロンプト内容
- エージェント間のデータ受け渡し方法
- 対象モデル

**ステップ2: 5軸レビュー**
全軸を順序通りチェック。問題がない軸も「問題なし」と明示する。

**ステップ3: 結果出力**
以下フォーマットで返却。

## 5 Review Axes

### 軸①: ツール設計

**検査内容**
- 削除・送信・課金操作が `bash` のままでないか
- ユーザー確認が必要な操作は専用ツール化されているか
- ログ・監査対象操作は専用ツール化されているか

**問題判定**: 取り消せない操作が bash で実装されている場合

### 軸②: 静的・動的の順序

**検査内容**
- システムプロンプト・ツール定義（静的）が先に配置されているか
- 会話履歴・ツール結果（動的）が後に配置されているか
- セッション中のモデル切り替えがないか
- ツールの動的追加・削除がないか

**問題判定**: 動的コンテンツが静的コンテンツより前に配置されている場合

### 軸③: システムプロンプト設計

**トークン数目安**

| 範囲 | 評価 |
|------|------|
| 200以下 | 適切 |
| 200〜500 | 要確認 |
| 500超 | 問題あり（分離推奨） |

**検査内容**
- 複数タスクの詳細がプロンプトに詰め込まれていないか
- 各タスクをサブエージェントに分離できないか

### 軸④: マルチエージェント設計

（単一構成時はスキップを明示）

**検査内容**
- オーケストレーター / ワーカーの役割が明確か
- 各エージェントの役割を一文で説明できるか
- エージェント間のデータ型・構造が定義されているか
- 処理の重複・抜け漏れがないか

### 軸⑤: 陳腐化リスク

**検査対象処理例**
- 出力の強制短縮
- フォーマット正規化
- コンテキスト強制リセット
- 過度な回避指示

**必須項目**: 注釈と「モデル更新時に見直す」記載の有無

## Design Consultation Mode

個別の設計判断を求められた場合は会話形式で対応。根拠は以下から引く：
- 操作の取り消し可否
- 静的 / 動的の性質
- タスクの必要性
- モデルの処理能力
